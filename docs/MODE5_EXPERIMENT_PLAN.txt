Jandi MX-106R 2.0 Mode 5 canonical 실험 계획
================================================

이 문서는 README의 실행용 요약본이다. 충돌 시 README가 항상 우선한다.

1. 목적
-------
- 독립 MX-106R 2.0 한 개와 1-DOF 진자 시험대를 사용한다.
- 실제 사용할 Current-based Position Control(Operating Mode 5) 설정을 고정한다.
- firmware/electrical model이 아닌 current-domain closed-loop equivalent M1을 식별한다.
- 최초 모델은 aP, aD, Ktau_eff, delay, J_arm, Coulomb, viscous만 사용한다.

2. 실험 전 기록
--------------
- hardware.yaml: 포트, baudrate, ID, model number, encoder zero, direction, rate.
- controller.yaml: Drive/Operating Mode, P/I/D, FF, Profile, Goal Current/PWM과 limits, Bus Watchdog.
- bench/geometry.yaml: 고정 L1=0.10 m/L2=0.15 m, arm mass/COM/inertia, physical fixture 축 설명, gravity zero/sign 정의.
  MuJoCo equivalent hinge axis는 항상 [0,1,0]이다.
- bench/loads.yaml: 250/500/750 g 추의 개별 실측 질량.
- safety.yaml: 사람이 확인한 안전 한계와 pilot 파형.
- campaign.yaml: campaign ID, holdout 한 조건, 실행 순서와 seed.
- trajectories/*.yaml: pilot 후 승인한 실제 파형 수치.
- fit.yaml: 측정 근거가 있는 timestep, bounds, initial, normalization, seeds.

어떤 REQUIRED 값도 추측해 채우지 않는다. 필요한 null이 남으면 실제 실행은 차단된다.

3. 준비 검사
------------
  uv run jandi-r2s-mode5-check

check는 모터를 움직이지 않는다. LOCKED 항목을 실제 측정/설정값으로 채운다.
한 명령으로 전체 실험을 연속 실행하지 않는다. Pilot, static, delay, dynamic은 서로
독립된 명령이며 static/dynamic 실제 실행은 아래처럼 정확히 한 run씩 지정한다.

4. Pilot
--------
  uv run jandi-r2s-mode5-pilot
  uv run jandi-r2s-mode5-pilot --execute --confirm PILOT_MX106_MODE5
  # 실제 실행에는 pilot.mechanical_configuration과 같은 --confirm-setup도 추가한다.

가장 안전한 configuration에서 부호, fixture, current/PWM, 통신, 진동, 온도를 확인한다.
사람이 승인한 뒤에만 safety.yaml의 pilot_passed를 true로 변경한다.

5. Static calibration
---------------------
6 configurations x 2 approach directions x 3 repeats = 정확히 36 sweep이다.
각 sweep은 smooth inter-point transfer, approach, fixed settling hold, averaging 순서로 측정한다.
각 sweep의 고정 angle은 -90/-60/-30/0/+30/+60/+90 deg이다.
따라서 36 sweep에서 총 252개의 잠재 static plateau를 얻는다.

  uv run jandi-r2s-mode5-static --mechanical-configuration L1_m250 \
    --approach approach_positive --repeat 1 \
    --confirm-setup L1_m250 \
    --execute --confirm CALIBRATE_MX106_MODE5

한 점의 torque/current 비율을 final Ktau로 쓰지 않는다. 모든 질량/길이/각/branch를
robust regression하여 Ktau_eff와 aP prior를 구하고 whole-sweep run bootstrap으로 uncertainty를 보강한다.

6. Delay calibration
--------------------
  uv run jandi-r2s-mode5-delay --confirm-setup <configured-delay-mechanical> \
    --execute --confirm CALIBRATE_DELAY_MX106_MODE5

Goal Position GroupSyncWrite Tx-only 완료 host timestamp부터 Present Current onset까지 effective
delay를 측정한다. command event에서만 write하고 별도 고속 state polling을 허용하며, 실제 달성
state interval보다 높은 정밀도를 주장하지 않는다. 기계적 position onset은 사용하지 않는다.

7. Dynamic campaign
-------------------
6 configurations x 3 trajectories x 3 repeats = 정확히 54 runs이다.
세 trajectory는 accelerated_oscillation, slow_plus_highfreq, slowly_raise_lower이다.
repeat 1/2/3 모두 repeatability용이며 데이터 확인 전에 dynamic trajectory holdout configuration
하나를 고정한다. Static은 여전히 6 configuration 전체를 쓰므로 entirely unseen 조건은 아니다.

  uv run jandi-r2s-mode5-collect --mechanical-configuration L1_m250 \
    --trajectory accelerated_oscillation --repeat 1 \
    --confirm-setup L1_m250 \
    --execute --confirm COLLECT_MX106_MODE5

8. 식별
-------
  uv run jandi-r2s-mode5-fit

- Stage A: static data로 Ktau_eff/aP prior 및 branch/condition residual 계산.
- Stage B: delay probe로 delay prior 및 uncertainty 계산.
- Stage C: accelerated oscillation으로 aD initial/condition consistency 계산.
- Stage D: holdout 9 runs를 제외한 45 runs에서 aP/Ktau/delay를 고정하고
  aD, J_arm, Coulomb, viscous만 최적화한다. PWM-saturated sample은 primary loss에서
  제외하고 current-saturated sample은 current clip model과 flag를 유지한다.
- Stage E는 기본 비활성이다. Stage D/held-out residual 검토 뒤 필요할 때만 fit.yaml에서
  활성화하며, aP/Ktau/delay를 포함한 7개 값은 measured uncertainty bound 안에서만
  움직이고 static/delay prior regularization을 함께 적용한다.

9. 검증과 보고
--------------
  uv run jandi-r2s-mode5-validate --result results/<timestamp>_mode5_m1
  uv run jandi-r2s-mode5-report --result results/<timestamp>_mode5_m1

holdout configuration의 9 runs만 primary validation에 쓴다. trajectory/config/repeat별
position, velocity, current, steady-state, saturation/thermal/residual을 검토한다.
simulation RMSE repeat variation과 실측 repeat pair의 q/qdot/current RMSE는 별도 지표다.
held-out evidence 없이 복잡한 friction/backlash/thermal model로 확장하지 않는다.
validation 통과 전 whole-Jandi locomotion 설정을 자동 변경하지 않는다.

10. 데이터 계약
---------------
- raw는 overwrite하지 않는다. logical run 아래 attempt_NNN으로 invalid/incomplete retry도 보존한다.
  valid attempt가 둘 이상이면 selected_attempt.txt 또는 select-attempt CLI로 명시한다.
- Main은 50 Hz target을 생성하고 같은 target을 두 번 전송하여 100 Hz bus write를 유지하며,
  state block도 100 Hz로 읽는다. target/write/state rate는 각각의 timestamp series로 따로
  계산하고 interval/overrun 통계를 저장한다.
- Realtime Tick은 modulus 32768로 unwrap한다.
- Watchdog는 Torque ON 후 활성화/read-back하며 null이면 실제 실행을 잠근다.
- Hardware Error polling은 별도이며 state sample을 대체하지 않는다.
- monotonic timestamp, raw/SI, unwrapped tick, saturation, voltage/temperature,
  full register readback, config hash, firmware/model, validity를 저장한다.
- 과거 no_load/loaded와 step/triangle/sine은 configs/legacy 및 docs/legacy에 보존되며
  canonical 명령에서 자동으로 읽지 않는다.

11. 사용자가 확정할 값
----------------------
- hardware: port, baudrate, motor ID/model, encoder zero, position/current/PWM 부호, rate.
- controller: Drive Mode, Position P/D, Goal/Limit Current, Goal/Limit PWM read-back.
- geometry: L1/L2 fixture 일치 확인, 막대·허브·체결부 질량, COM 반경, 관성 및 그 기준, 축/영점/부호.
- loads: 250/500/750 g 추 각각의 실측 질량.
- safety: 각도·온도·전압·전류·PWM·속도·오차 한계, transition/rest, warm-up 및 acknowledgment timestamp.
- pilot/static/delay/dynamic trajectory의 모든 null 파형 수치.
- campaign ID, 실행 순서/seed, 데이터를 보기 전에 정한 holdout configuration.
- fit timestep, 측정 근거 bounds/initial, seeds/evaluation budget, normalized loss 값,
  static run-level bootstrap repeat/seed/condition-number threshold.

12. 실행 순서
------------
jandi-r2s-mode5-check가 valid raw run을 기준으로 NEXT STATIC/NEXT COLLECT를 표시한다.
실행 요청이 NEXT와 다르면 차단한다. 불가피한 순서 변경은 --override-order와 비어 있지 않은
--override-reason을 함께 쓰며 그 사유는 metadata에 기록한다.

13. GUI
-------
  uv run jandi-r2s-mode5-gui --mock   # 명시적 하드웨어 없는 확인
  uv run jandi-r2s-mode5-gui          # Connect 전에는 port를 열지 않음

Preview는 port 없이 동작한다. 실제 RUN은 physical setup confirmation, 기존 confirmation 문자열,
required-value gate와 planned order를 그대로 통과해야 한다. 빨간 TORQUE OFF는 항상 표시하며
물리 전원 차단을 대체하지 않는다. Manual telemetry는 data/temp/manual에만 저장한다.
