Jandi MX-106R 2.0 Current-based Position Control 등가 액추에이터 실험 계획서
===============================================================================

문서 상태
---------
- 대상: MX-106R 2.0, Protocol 2.0, Operating Mode 5
- 목적: Jandi MuJoCo 보행 학습에 사용할 최소 등가 액추에이터 모델 식별
- 실험 대분류: no_load / loaded
- 각 대분류의 중분류: step / triangle / sine
- 반복: 각 조합 3회, 총 18회
- 원칙: 1·2회는 계산/fit, 3회는 validation 전용
- 중요: 이 문서는 실제 DYNAMIXEL firmware나 PWM 전기회로 전체를 복원하는
  계획이 아니다. 고정된 Mode 5 register 설정에서 관측되는 입출력 특성을
  MuJoCo에서 재현하는 계획이다.


1. 연구 질문과 최종 산출물
===========================

1.1 연구 질문
-------------
고정된 MX-106 설정에서 Goal Position q_target을 100 Hz로 전달했을 때,
Present Position, Velocity, Current가 어떤 지연과 동특성을 보이는가?

이 동작을 다음 최소 모델로 설명할 수 있는가?

  e(t) = q_target(t - delay) - q(t)
  I_model(t) = clip(aP * e(t) - aD * q_dot(t), -I_cap, I_cap)
  tau(t) = Ktau * I_model(t)

  MuJoCo joint:
    armature     = J_eff
    frictionloss = Fc
    damping      = Bv

초기 모델에서는 aD=0을 기본으로 둔다. Sine validation에서 P-only 모델보다
반복적으로 좋아질 때만 aD를 채택한다.

1.2 최종 산출물
---------------
1) 원본 telemetry와 command timestamp
2) 모든 DYNAMIXEL register의 실제 read-back 기록
3) delay, aP, Ktau, J_eff, Fc, Bv 및 선택적인 aD
4) repeat 3의 held-out 검증 지표와 그래프
5) MuJoCo에 넣을 params_mode5.yaml
6) 실험 장치 사진, 치수, 전원 및 온도 기록

1.3 초기 단계에서 고의로 제외하는 항목
---------------------------------------
- 상세 PWM switching 및 winding electrical model
- Stribeck friction
- 방향별 마찰
- 하중 의존 마찰
- 백래시
- 온도 의존 모델
- 신경망 액추에이터 모델

이 항목은 repeat 3 잔차에서 같은 패턴이 반복될 때만 다음 모델로 검토한다.


2. 실험 분류
============

2.1 대분류 A: no_load
----------------------
출력축에는 혼만 장착하고 시험 막대기와 무게추를 모두 제거한 상태다.

목적:
- 명령-전류 유효 지연 확인
- 작은 부하에서 위치오차-전류 관계 확인
- 기본 transient와 속도 응답 확인
- 시험대 자체 마찰과 암 관성의 기초 정보 확보

2.2 대분류 B: loaded
--------------------
출력축에 알려진 막대기와 하나의 알려진 추를 정해진 반경에 장착한다.
막대기·추의 종류와 위치는 실험 전체에서 바꾸지 않는다.

목적:
- known gravitational torque와 Present Current를 이용한 Ktau 추정
- 부하가 바뀌어도 aP와 delay가 유지되는지 확인
- J_eff, Fc, Bv가 두 조건을 동시에 설명하는지 검증

2.3 중분류 1: step
------------------
한 run에서 center와 ±small, ±medium, ±large를 순서대로 적용한다.

목적:
- Goal Position 송신부터 Present Current 반응까지 delay
- transient 상승/감쇠/overshoot
- 정착구간의 e와 current 관계에서 aP
- loaded 정착구간의 중력토크와 current 관계에서 Ktau

2.4 중분류 2: triangle
----------------------
저속과 중저속 삼각파를 한 run에 순서대로 적용한다.

목적:
- 거의 일정한 속도 구간 확보
- 방향 전환 전후의 Coulomb/static friction 단서
- 속도에 따른 전류 차이로 viscous friction 단서

2.5 중분류 3: sine
------------------
낮은 주파수부터 높은 주파수까지 각각 단일 sine을 이어서 적용한다.
여러 주파수를 한 번에 합친 multisine 대신 단일 sine을 쓰므로 초보자도
주파수별 결과를 직접 판독할 수 있다.

목적:
- 주파수에 따른 phase lag와 amplitude attenuation
- J_eff 및 Bv 계산
- aD 후보가 실제 Present Current 예측을 개선하는지 검증

2.6 총 실험 수
---------------

  no_load: step 3회 + triangle 3회 + sine 3회 = 9회
  loaded : step 3회 + triangle 3회 + sine 3회 = 9회
  합계   : 18회

같은 run 내부에 여러 진폭/주파수를 넣었으므로 별도의 delay campaign,
static campaign, dynamic campaign을 추가하지 않는다.


3. 실험 장치와 계측값
=====================

3.1 필수 장치
-------------
- MX-106R 2.0 한 개
- 단단한 고정 프레임
- 출력축에 결합한 강체 암
- 위치가 고정되는 알려진 무게추 한 개
- 12 V급 안정화 전원과 충분한 전류 용량
- USB-DYNAMIXEL interface
- 즉시 전원을 끊을 물리 비상 차단 수단
- 자 또는 캘리퍼스, 질량 측정 수단
- 실험 장치 사진을 찍을 카메라

3.2 반드시 측정하여 YAML에 기록할 값
-------------------------------------
- arm_mass_kg
- arm_com_radius_m: 회전축에서 암 자체 COM까지 거리
- arm_inertia_kg_m2: 출력축 기준 암 관성
- added_load_mass_kg
- added_load_radius_m: 회전축에서 추 COM까지 거리
- gravity_zero_offset_rad
- motor_id, zero_tick, direction
- software_min_rad, software_max_rad, center_rad

질량 또는 COM을 정확히 모르면 임의 숫자를 넣지 않는다. null 상태에서는
실기체 실행이 잠기도록 패키지가 구성되어 있다.

3.3 좌표계
----------
- q의 양의 방향은 YAML direction이 정의한다.
- encoder 1 tick은 2*pi/4096 rad이다.
- Current와 PWM도 같은 관절 양의 방향으로 부호 변환하여 저장한다.
- 중력토크 계산은 q + gravity_zero_offset_rad를 사용한다.

실험 전 손으로 아주 작은 양의 명령을 주는 pilot에서 q, velocity, current의
부호가 일관되는지 확인한다.


4. 고정 DYNAMIXEL 설정
======================

4.1 실험 중 변경하지 않는 항목
-----------------------------
- Operating Mode = 5
- Position P/I/D Gain
- Feedforward 1st/2nd Gain
- Profile Velocity/Acceleration
- Goal Current
- Current Limit
- Goal PWM
- PWM Limit
- Bus Watchdog
- 공급전압 조건

이 값은 identification parameter가 아니다. 실제 Jandi에서 쓸 값을 먼저
결정하고 모든 run에서 똑같이 적용한다.

4.2 자동 설정 순서
------------------
수집기는 매 run에서 다음 순서를 수행한다.

1) 포트 열기와 motor ping
2) Torque OFF
3) Operating Mode가 5인지 확인하고 필요할 때 변경
4) Mode 변경 뒤 P/I/D, feedforward, profile을 다시 기록
5) Goal Current, Goal PWM, Bus Watchdog 기록
6) Current Limit, PWM Limit을 포함한 register 재읽기
7) YAML 기대값과 하나라도 다르면 중단
8) 현재 위치를 첫 Goal Position으로 기록
9) Torque ON
10) 5초 cosine transition으로 center 이동
11) transition은 식별 telemetry에 포함하지 않음
12) 본 trajectory 실행
13) 성공·실패와 관계없이 Torque OFF 시도

Mode 5에서는 EEPROM Min/Max Position Limit에 의존하지 않는다. 모든 Goal
Position은 Python의 software_min/max 범위를 먼저 통과해야 한다.


5. 파일과 로그 계약
===================

5.1 원본 데이터 경로
--------------------

data/raw/mode5/<campaign-id>/
  no_load/
    step/repeat_1 ... repeat_3
    triangle/repeat_1 ... repeat_3
    sine/repeat_1 ... repeat_3
  loaded/
    step/repeat_1 ... repeat_3
    triangle/repeat_1 ... repeat_3
    sine/repeat_1 ... repeat_3

각 repeat 폴더:
- telemetry.csv
- command_events.csv
- metadata.json

기존 폴더는 overwrite하지 않는다. 같은 campaign id를 재사용하면 실행을
거부하므로 잘못된 run도 삭제하지 말고 새 campaign id로 다시 측정한다.

5.2 telemetry.csv 핵심 열
------------------------
- host/tx/rx timestamp
- cycle_index, phase, overrun_ns
- q_cmd, q_present, dq_present
- Present Current raw와 A
- Present PWM raw와 percent
- Position/Velocity Trajectory
- voltage, temperature, realtime tick
- hardware error

5.3 command_events.csv
----------------------
모든 100 Hz 명령의 sequence, 예정시간, Goal Position, tx 시작/종료 시간을
따로 저장한다. delay는 이 송신시각과 Present Current onset을 비교한다.

5.4 metadata.json
-----------------
- condition, trajectory, repeat, fit/validation 역할
- 사용한 YAML 절대경로와 SHA-256
- motor model number
- 실제 register read-back
- bench geometry
- 시작/종료시각
- valid_flag와 invalid_reason


6. 안전 절차
============

6.1 실행 전 작업자 체크리스트
----------------------------
[ ] DYNAMIXEL Wizard가 포트를 점유하지 않는다.
[ ] 암과 추의 체결이 풀리지 않는다.
[ ] 회전 범위 안에 사람, 케이블, 공구가 없다.
[ ] software limit가 기계 hard stop보다 충분히 안쪽이다.
[ ] 물리 전원 차단 스위치에 즉시 손이 닿는다.
[ ] Mode 5 P/D와 Goal Current/PWM 값을 기록했다.
[ ] 공급전압과 전류 용량을 확인했다.
[ ] no_load 또는 loaded 장착 상태가 YAML과 일치한다.
[ ] 먼저 dry-run plan을 확인했다.
[ ] ±2° pilot에서 부호, 진동, current, PWM을 확인했다.

6.2 자동 중단 조건
------------------
- Hardware Error Status 비영
- 통신 오류
- 설정 read-back 불일치
- software position limit 초과 명령
- 연속 표본에서 과전류
- 연속 표본에서 과도한 PWM
- 저전압
- 과온
- 과도한 position error

단일 통신 spike로 바로 중단하지 않도록 일반 상태 한계는 연속 표본 수를
사용한다. Hardware Error는 발견 즉시 중단한다.

6.3 Pilot 승인 절차
------------------
초기 YAML의 pilot_approved는 false다. 다음을 직접 확인하기 전에는 true로
바꾸지 않는다.

1) safety.pilot_amplitude_rad가 약 2°인지 확인하고 pilot dry-run
2) no_load에서 다음 별도 pilot을 한 번 실행

     uv run jandi-r2s-mode5-collect --condition no_load --pilot \
       --execute --confirm PILOT_MX106_MODE5

3) 소음, 진동, 방향, 전류, PWM, 온도, 전압강하 확인
4) center로 안전하게 복귀하는지 확인
5) 확인 후 YAML의 pilot_approved를 true로 변경
6) loaded 본 실험도 step부터 관찰하며 진행


7. 실제 실험 절차
=================

7.1 최초 설정
-------------
터미널:

  cd /home/noh/Jandi_real2sim
  uv sync
  uv run jandi-r2s-mode5-check

check 출력의 null 항목을 다음 책임에 맞는 파일에 채운다.

  configs/mode5/hardware.yaml
  configs/mode5/controller.yaml
  configs/mode5/bench/no_load.yaml
  configs/mode5/bench/loaded.yaml
  configs/mode5/trajectories/step.yaml
  configs/mode5/trajectories/triangle.yaml
  configs/mode5/trajectories/sine.yaml

campaign 조합과 반복·안전 한계는 configs/mode5/campaign.yaml에서 관리한다.
no_load는 모터+혼만이므로 질량·COM·외부 관성을 0으로 기록한다. loaded에는
막대기와 추의 실측값을 별도로 기록한다. 로더는 loaded에 대해 다음을 계산하여
metadata에 원시 치수와 함께 기록한다.

  m_eq = m_arm + m_load
  r_eq = (m_arm*r_arm + m_load*r_load) / m_eq
  J_eq,pivot = J_arm,pivot + m_load*r_load^2

check가
18개 run의 예상 시간과 실행 잠금 여부를 출력한다.

7.2 Dry-run
-----------

  uv run jandi-r2s-mode5-collect --condition no_load
  uv run jandi-r2s-mode5-collect --condition loaded

이 명령은 포트를 열지 않고 18개 plan과 metadata만 만든다. plan.csv의
첫/마지막 각도, 최대/최소 tick, 총 시간을 확인한다.

7.3 no_load 수집
----------------
추를 장착하지 않은 상태를 사진으로 남긴다.

  uv run jandi-r2s-mode5-collect \
    --condition no_load \
    --execute --confirm MOVE_MX106_MODE5

실행 순서는 step repeat 1~3, triangle repeat 1~3, sine repeat 1~3이다.
각 run 사이에 자동 대기가 있지만 작업자는 온도와 체결 상태를 다시 본다.

7.4 loaded 수집
---------------
전원을 끄고 알려진 추를 YAML에 기록한 반경에 장착한다. 사진에 회전축과
추 COM까지의 길이가 보이도록 자를 같이 촬영한다.

  uv run jandi-r2s-mode5-collect \
    --condition loaded \
    --execute --confirm MOVE_MX106_MODE5

7.5 중단 후 처리
---------------
실패 run은 metadata의 valid_flag=false로 남긴다. 같은 폴더를 덮어쓰지
않는다. 원인을 기록하고 campaign id를 새로 만든 뒤 해당 조건만 다시 한다.


8. 계산 및 식별 절차
====================

8.1 데이터 분할
-------------
- repeat 1, 2: 계산/fit
- repeat 3: validation

인접 sample을 무작위로 train/validation에 나누지 않는다.

8.2 Delay
---------
step의 Goal Position 변화 송신시각과 Present Current가 baseline noise를 넘어선
첫 시각의 차이를 구한다. 양/음 방향과 세 진폭을 모두 보고 median, mean,
표준편차, min/max를 저장한다. q가 움직이기 시작한 시각은 delay로 쓰지 않는다.

8.3 aP
------
step plateau의 마지막 35%에서 q_dot가 거의 0인 표본을 사용한다.

  I = aP * (q_cmd_delayed - q) + bias

Current/PWM 포화 표본은 제외한다. no_load와 loaded에서 기울기가 크게 다르면
단일 aP 확정을 보류한다.

8.4 Ktau
--------
arm과 added load의 중력토크를 계산한다.

  G = g * (m_arm*r_arm + m_load*r_load)
  tau_required = G * sin(q + gravity_zero_offset)
  tau_required = Ktau * I + torque_bias

Ktau 회귀에는 알려진 중력토크가 존재하는 loaded plateau만 사용한다.
CW/CCW 접근 차이와 bias가 크면
정지마찰 또는 좌표오류를 먼저 의심한다.

8.5 aD 채택 규칙
----------------
Sine repeat 1·2에서 다음 두 모델을 비교한다.

  P-only: I = aP*e + b
  P-D   : I = aP*e - aD*q_dot + b

repeat 3에서 aD가 양수이고 current RMSE가 P-only보다 최소 10% 반복 개선될
때만 채택한다. 아니면 aD=0을 유지한다.

8.6 J_eff, Fc, Bv
-----------------
triangle과 sine repeat 1·2에서 q를 평활 미분하여 q_dot, q_ddot을 구한다.

  Ktau*I - G*sin(q+offset)
    = J_eff*q_ddot + Bv*q_dot + Fc*sign(q_dot)

이 선형 회귀는 최소 초기값을 구하는 용도다. 결과가 음수이거나 경계적으로
불안정하면 물리값으로 강제하지 말고 좌표, 하중치수, derivative noise,
포화 구간을 먼저 점검한다.

8.7 실행 명령
-------------

  uv run jandi-r2s-mode5-fit
  uv run jandi-r2s-mode5-compare \
    --params results/정확한_결과폴더/params_mode5.yaml

fit 결과:
- results/<timestamp>_mode5_minimal/params_mode5.yaml
- metrics.json
- report.md
- config_manifest.json: 모든 분리형 설정 경로·SHA-256과 해석된 시험대 값

compare 결과:
- 18개 q_cmd/q_real/q_sim, dq_real/dq_sim, I_real/I_model 비교 그림
- run별 position/velocity/current 오차 metrics.json
- 사용한 campaign과 파라미터의 정확한 경로 manifest.json

compare는 timestamp가 가장 최신인 결과를 자동 선택하지 않는다. 반드시 검토할
params_mode5.yaml의 정확한 경로를 명령에 쓴다.


9. 결과 판정 기준
=================

9.1 반드시 condition별로 볼 지표
--------------------------------
- position MAE/RMSE
- current prediction RMSE
- step peak timing
- settling time와 overshoot
- 정상상태 위치오차
- current/PWM saturation 비율
- command 주기와 overrun 분포
- 온도 및 입력전압 변화

9.2 모델 복잡도를 늘리는 조건
------------------------------
다음 패턴이 repeat 3과 양쪽 부하에서 반복될 때만 늘린다.

- 0속도 부근 방향반전 잔차: static/Stribeck 후보
- CW/CCW 정상상태가 다름: 방향 마찰 또는 backlash 후보
- 고속/PWM 상한에서만 오차: voltage/back-EMF 후보
- 온도에 따라 연속 drift: thermal 후보

한 그림에서 한 번 보인 현상만으로 파라미터를 추가하지 않는다.

9.3 실패로 판단할 경우
---------------------
- repeat 간 결과 변동이 파라미터 효과보다 큼
- delay가 진폭/방향마다 전혀 다름
- aP 또는 Ktau 부호가 예상과 반대
- J_eff/Fc/Bv가 음수 또는 비현실적 경계값
- validation이 단순 baseline보다 나쁨

이때 optimizer 범위를 넓히기 전에 실험 장치, 좌표, register read-back,
timestamp, 포화, 하중 치수를 다시 확인한다.


10. 논문 Methods에 기록할 내용
==============================

10.1 Hardware
-------------
- motor model, firmware, ID, baudrate, protocol
- 공급전압과 전원 사양
- 시험대 구조와 사진
- arm/load 질량, COM 반경, 관성
- encoder 영점과 좌표 정의

10.2 Controller
---------------
- Operating Mode 5
- P/I/D, feedforward, profile
- Goal Current/Current Limit
- Goal PWM/PWM Limit
- Bus Watchdog
- 모든 실제 read-back 값

10.3 Acquisition
----------------
- Goal Position command 100 Hz
- state 99 slots/s, Hardware Error 1 slot/s
- host monotonic tx/rx timestamps
- Present Position/Velocity/Current/PWM/Voltage/Temperature
- SI 변환계수와 raw 동시 보존

10.4 Protocol
-------------
- no_load와 loaded 각각 step/triangle/sine 3회
- run 순서와 run 사이 대기
- pilot 및 abort 기준
- repeat 1·2 fit, repeat 3 validation

10.5 Identification
-------------------
- delay onset 정의
- plateau 선택 비율
- aP/Ktau regression 식
- aD 채택 규칙
- J/Fc/B regression 식과 평활미분 방법
- 포화/invalid 표본 처리

10.6 주장 범위
--------------
가능한 주장:
  고정된 MX-106 Mode 5 설정에서 관측되는 current-domain controller와 출력축
  동특성을 재현하는 physics-informed equivalent model을 식별했다.

피해야 할 주장:
  DYNAMIXEL firmware, 전기회로, PWM switching을 완전히 복원했다.


11. Jandi 적용
==============

Standalone validation을 먼저 끝낸다. 이후 Jandi MuJoCo에서는:

- policy target: 50 Hz, 20 ms ZOH
- motor command interface: 100 Hz
- 식별 delay 적용
- current-domain controller는 physics step마다 계산
- current clip 후 tau=Ktau*I
- joint armature/frictionloss/damping 적용

전체 로봇 결과가 다르다고 standalone actuator 파라미터를 즉시 다시 맞추지
않는다. 먼저 link mass/inertia, COM, 관절축, 발 접촉, 지면마찰, 센서 지연을
점검한다.
